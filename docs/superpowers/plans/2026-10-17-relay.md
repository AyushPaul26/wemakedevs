# Relay Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development or superpowers:executing-plans to implement the tasks. The user's instruction to start authorizes execution of the agreed product; do not introduce another routine confirmation gate.

**Goal:** Deliver the Meridian company assistant and Ripple demo with real FalkorDB storage and a usable, verified browser interface.

**Architecture:** FastAPI orchestrates LangGraph workflows and a direct FalkorDB repository. React/TypeScript combines a graph canvas, assistant, sources, persistent memory, and actions. Model access is configurable, with an explicitly labelled deterministic demo when credentials are absent.

**Tech Stack:** Python 3.12, FastAPI, FalkorDB/falkordb-py, LangGraph SQLite checkpointer, React/TypeScript/Vite, React Flow, assistant-ui; optional GraphRAG SDK and Graphify importer.

**Spec:** `docs/relay-product-spec.md`

## Global Constraints

- FalkorDB is the primary graph database; no in-memory substitute for required DB validation.
- Keep API shapes from the spec consistent across separately implemented modules.
- Use the existing isolated cloud checkout. No worktree, external action, commit, push, or deployment is needed.
- Never claim a model invocation, document extraction, or task execution occurred when only a demo/preview was produced.
- Preserve source evidence and distinguish hypothetical assumptions from factual graph state.

## Review Focus

- Wrong-direction dependency traversal: test known reverse/non-impact pairs.
- Duplicate approval or request retry: test repeated transitions do not duplicate tasks.
- Missing DB or model service: test truthful, actionable failure response and retained user input.
- Restarted services: test persisted memories and workflow checkpoint IDs.
- Long questions/source text and narrow screens: validate limits, wrapping, scroll, and keyboard access.
