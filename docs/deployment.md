# Test Relay on Render

The repository includes a single-container Render Blueprint on the `work` branch. It serves the built frontend and API together, with the pinned FalkorDB database bound only to container loopback. The Blueprint selects the free plan and disables automatic deployments.

1. Open [Deploy Relay on Render](https://dashboard.render.com/blueprint/new?repo=https%3A%2F%2Fgithub.com%2FAyushPaul26%2Fwemakedevs). Sign in and connect this GitHub repository if prompted. Select branch `work` and confirm the free service plan.
2. Create the Blueprint and wait for its web service to become healthy. Render provides the actual `https://…onrender.com` app URL; the setup link above is not the running app.
3. Open the service's **Environment** settings. `RELAY_ACCESS_PASSWORD` is generated by Render. Use username `relay` and that password when the app prompts for browser authentication.
4. For live answers, add `RELAY_MODEL_API_KEY` as a secret environment value in Render and redeploy. The configured provider is Groq. Without this key the app explicitly uses guided demo mode. Never put credentials in Git or a frontend variable.

This is a test instance with temporary storage. Free Render instances can sleep, take time to wake, and lose newly added notes, memory, and tasks when replaced or redeployed. The fictional sample company is reseeded. Keep the existing cloud workspace for durable development data. A paid persistent disk or separate persistent FalkorDB service is a future deployment choice, not configured by this Blueprint.

## Automated deployment from Codex

The Render REST API needs `RENDER_API_KEY`, supplied securely through cloud environment settings with destination `api.render.com`. Codex can then discover the workspace using `GET /v1/owners`, create the free Docker web service from the `work` branch, and verify Render's returned service URL. GitHub repository access must also be authorized in Render. Saving these requirements is separate from supplying credentials, applying network settings, and actually deploying the service.

## Container validation

Build using `docker build -t relay-preview .`. In this managed cloud environment use the provided proxy and CA bundle:

```sh
BUILDX_CONFIG=/workspace/.cache/docker-buildx docker build \
  --secret id=proxy_ca,src=/etc/ssl/certs/ca-certificates.crt \
  -t relay-preview .
```

Run with `RELAY_ACCESS_PASSWORD` supplied through a private environment file or your container platform's environment settings. The password must contain at least 16 characters. Expose only port 10000, and use HTTPS at the hosting boundary. `/api/health` is public for hosting health checks; all app pages and other API routes require authentication. Missing credentials stop the container. The Docker build context excludes local keys, development data, Git metadata, and dependency caches.

The free Blueprint fields were checked against Render's [official Docker example](https://github.com/render-oss/skills/blob/main/skills/render-deploy/assets/docker.yaml) and deployment references. A local build/test is not proof of a Render deployment or available hosting quota.
